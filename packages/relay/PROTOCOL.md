# Daisy 中转协议

版本：**1**（协议主版本；路径 `/v1/…`、每条消息的 `v` 都是它）　文档修订：1.1（2026-11-18，安全审查第一轮，见文末“修订记录”；没有发布过，协议版本仍是 1）

依据：ADR-100（A1 按 SNI 透传 TLS、C1 控制连接 + 每个外来连接反连一条数据连接、D1 不在线在握手阶段拒绝 + 在线查询）、D-05、D-41、ADR-099（身份密钥）、identity-card.md（身份编号）。代码里的常量在 `src/protocol.ts`，必须与本文一致（`tests/relay-package.test.ts` 核对）。

本文写给两类人：实现 Daisy 一侧的人（P5-02），和想自己实现一个兼容中转的人。

---

## 1. 角色和一句话

- **中转**有一个域名 `D`（例：`relay.example`）和一个公网端口（生产 443）。它只终止 `D` 自己的 TLS；`<子域名>.D` 的 TLS 一律原样透传，不终止。
- **Daisy** 主动连到 `wss://D/v1/control` 并保持，用身份私钥签挑战登记；拿到固定地址 `https://<子域名>.D`。
- **调用方**（别的 Daisy、第三方 A2A 客户端、浏览器）对 `<子域名>.D:443` 发起普通 TLS。中转读 ClientHello 里的 SNI，通知 Daisy，Daisy 新开一条数据连接认领，中转在两边之间原样搬字节。TLS 在调用方和 Daisy 之间端到端完成，中转只看到 SNI 和密文。

中转**不**保存任何请求、**不**终止 Daisy 子域名的 TLS、**不**判断谁能调用谁、**不**做穿透。

## 2. 子域名

子域名 = Daisy 身份公钥的 RFC 7638 指纹（SHA-256，32 字节）的**前 160 位（20 字节）**，RFC 4648 base32、小写、不带填充，**32 个字符**，`[a-z2-7]{32}`。

因为 160 位正好是 32 个 base32 字符，子域名就是 52 字符身份编号的**前 32 个字符**。手里有对方名片的调用方可以自己算出对方的中转地址。

中转只把子域名分给能用对应私钥签出本连接挑战的那一方（第 4 节）；客户端不能自己指定子域名，消息里多带的字段一律忽略。

## 3. 公网端口上的分流

中转读入站连接的 TLS ClientHello（可以跨多个记录），只取 `server_name`（RFC 6066），按下表处理：

| SNI | 处理 |
| --- | --- |
| 等于 `D` | 交给中转自己的 HTTPS 服务（第 4–7 节的接口）。这是中转唯一终止的 TLS |
| `<子域名>.D`，该 Daisy 在线，未超上限 | 发 `open`（第 5 节），等 Daisy 认领后原样转发 |
| `<子域名>.D`，该 Daisy 不在线 | 回 TLS 警报 `unrecognized_name`（112），关闭（D1）。不保留任何东西 |
| `<子域名>.D`，在线但超上限、Daisy 拒绝、或没在认领时限内认领 | 回 TLS 警报 `internal_error`（80），关闭 |
| 其他名字、没有 SNI | 回 `unrecognized_name`，关闭；日志里不写这个名字 |
| 不是 TLS、ClientHello 畸形或超长、在时限内没收全 | 直接关闭，不回任何字节 |

警报是一条明文 TLS 记录：`15 03 03 00 02 02 <描述>`。调用方看到的是握手失败（第三方客户端只看到连接错误，D-41 ①）。Daisy 自己的客户端应先查在线状态（第 7 节）再显示“对方不在线”。

## 4. 控制连接：登记

`GET wss://D/v1/control`（WebSocket，RFC 6455；不协商压缩）。所有控制消息是 UTF-8 JSON 文本帧，单条不超过中转的 `maxControlMessageBytes`（默认 8 KiB）。

升级请求**不能带 `Origin` 头**（带了一律 403：只有 Daisy 连这里，网页不行）。同一来源（IPv4 地址；IPv6 按 /64，另按 /56、/48 合计）同时未登记的控制连接有上限（`maxUnauthControlsPerIp`，默认 8），超出 429；全中转合计超出 503。

1. 连上后中转先发：
   ```json
   {"t":"challenge","v":1,"nonce":"<32 字节随机数的 base64url>","aud":"relay.example"}
   ```
2. Daisy 在 `helloTimeoutMs`（默认 3 秒）内回**一条**：
   ```json
   {"t":"hello","v":1,"proof":"<JWS 紧凑序列化>"}
   ```
   `proof` 是用 Ed25519 身份私钥签的 JWS：
   - 头**恰好**是 `{"alg":"EdDSA","typ":"daisy-relay-proof+jwt"}`，不能有 `jwk`、`kid`、`jku`、`x5u`、`crit` 等其他成员。`typ` 与身份名片（`daisy-card+jwt`）、访问令牌（`at+jwt`）都不同，三者的签名不能互相顶替。
   - 载荷：
     ```json
     {"v":1,"aud":"relay.example","nonce":"<挑战里的 nonce>","key":{"kty":"OKP","crv":"Ed25519","x":"<公钥 base64url>"}}
     ```
     `key` 只能有这三个成员（带私钥 `d` 拒绝）。
3. 中转逐项检查，任何一项不过都以关闭码 4401 断开：头、`v`、`aud` 等于自己的域名、`nonce` 等于**本连接**发出的那个（所以截获的证明换一条连接就没用）、`key` 合法、签名在 `key` 下成立。通过后回：
   ```json
   {"t":"welcome","v":1,"subdomain":"<32 字符>","host":"<子域名>.relay.example","id":"<52 字符身份编号>",
    "limits":{"claimTimeoutMs":5000,"maxStreams":64,"pingIntervalMs":20000,"maxDataFrameBytes":65536}}
   ```
   Daisy 应核对 `id` 等于自己的身份编号、`host` 是自己期望的。
4. 同一把钥匙再次登记成功时，**新连接取代旧连接**：旧连接收到关闭码 4409。只有持有私钥的一方能做到，所以这不是抢占；它让一条悄悄断掉的旧连接不必等心跳超时。不同的钥匙得到不同的子域名，碰不到别人的。
5. 已经有 `maxDaisys` 个 Daisy 在线，或同一来源已有 `maxDaisysPerIp`（默认 128）个在线时，新的 Daisy（不是已在线的那把钥匙）以 4503 被拒。
6. 运营方可以配置允许名单（`allowIdentities`，身份编号）。配了以后，名单外的钥匙证明正确也以 **4403** 被拒。

## 5. 外来连接：open → 认领 → 转发

1. 有调用方连 `<子域名>.D` 时，中转在该 Daisy 的控制连接上发：
   ```json
   {"t":"open","v":1,"n":17,"claim":"<32 字节随机数的 base64url>","addr":"203.0.113.9"}
   ```
   - `n`：流水号，只用于两边日志对照，不是秘密。
   - `claim`：一次性的认领凭据，**不要写进日志**。
   - `addr`：中转看到的调用方地址，仅供 Daisy 做自己的频率限制参考（Daisy 无法验证它）。
2. Daisy 在 `claimTimeoutMs`（默认 5 秒）内新开 `GET wss://D/v1/data`，**认领凭据放在升级请求的头里**：
   ```
   daisy-relay-claim: <同上>
   ```
   中转在升级之前就检查：凭据不认识、用过、过期、没带 → **HTTP 404**，不建立 WebSocket；带 `Origin` 头 → 403。凭据只能用一次（检查通过的那一刻就作废）。这条数据连接算在它的 Daisy 名下（`maxStreamsPerDaisy`），不占它所在地址的连接数和请求频率。
3. 升级成功（101）后，中转立即把它已读到的 ClientHello 字节作为二进制帧发给 Daisy，然后双向转发：调用方的字节 → 二进制帧给 Daisy；Daisy 发来的二进制帧 → 原样写给调用方。**只允许二进制帧**，文本帧会让中转切断这条流（4400）。**Daisy 发的每一帧不超过 `maxDataFrameBytes`**（welcome 里给出，默认 64 KiB），更大的写要拆开；超过的帧让中转以 1009 关闭。帧的边界没有意义，Daisy 把收到的帧当作一条字节流，接到自己“对外面”的 TLS 服务端（ADR-101），TLS 在 Daisy 这里终止。
   中转每条流每个方向最多排队 `streamWindowBytes`（默认 256 KiB），超过就停止读来源一侧（WebSocket 或 TCP 的流控自然把压力传回发送方）；全中转排队字节有总预算（`maxBufferedBytes`），超出时新的外来连接以 `internal_error` 拒绝。
4. 关闭：调用方断开 → 中转把已排队的字节交给 Daisy 后关闭数据连接（1000）。Daisy 关闭数据连接 → 中转把已排队的字节写给调用方后关闭 TCP。另一边在 `streamCloseGraceMs`（默认 5 秒）内没取走就切断；在彻底关掉之前，这条流仍算在 Daisy 的流数里。超上限、出错 → 两边立即切断（数据连接上带关闭码 4413 或 4400）。
5. Daisy 不想接（比如到了自己的上限）可以在控制连接上发 `{"t":"reject","v":1,"claim":"<claim>"}`，中转立即以 `internal_error` 拒绝调用方。

## 6. 心跳、断线和重连

- 中转每 `pingIntervalMs`（默认 20 秒）在控制连接上发 WebSocket ping；到下一次 ping 时还没收到 pong，就断开并视为离线。Daisy 侧照常回 pong（WebSocket 库自动做），并且**超过 2.5 × `pingIntervalMs` 没收到 ping 时自行断开重连**。
- Daisy 离线时，它还没被认领的外来连接立即以 `unrecognized_name` 拒绝；已经在转发的流不受影响，直到任一端关闭。
- 中转重启时向所有控制连接发关闭码 **1012**。Daisy 断线后按“基数 × 2^次数、不超过上限、乘以 0.5–1 的随机因子”退避重连（建议基数 1 秒、上限 30 秒；收到 1012 可从基数重来），登记成功后清零。计划 9.1：中转重启后 30 秒内连回。

关闭码一览：

| 码 | 含义 |
| --- | --- |
| 1000 | 正常关闭（数据连接） |
| 1009 | 消息超过上限（WebSocket 标准码） |
| 1012 | 中转重启，稍后重连 |
| 4400 | 协议错误：消息畸形或不该出现 |
| 4401 | 登记证明被拒 |
| 4403 | 这个身份不在运营方的允许名单里 |
| 4408 | 超时：没在时限内发 hello |
| 4409 | 同一把钥匙的新连接取代了这条 |
| 4413 | 流超过字节或时长上限（数据连接） |
| 4429 | 消息太多 |
| 4503 | 中转已满（`maxDaisys`），或这个来源的 Daisy 已满（`maxDaisysPerIp`） |

数据连接的认领失败不再是关闭码：升级前就以 HTTP 404 拒绝（见第 5 节）。

## 7. 中转自己的 HTTPS 接口

只在 SNI 为 `D` 时可达。每个连接只处理一个请求（`connection: close`），只接受 `GET`/`HEAD`。TLS 握手、请求头各有**绝对**时限（逐字节拖延也到点断开）。

| 路径 | 回答 |
| --- | --- |
| `GET /v1/info` | `{"v":1,"relay":"daisy-relay","protocols":[1],"domain":"relay.example"}` |
| `GET /v1/presence/<子域名>` | `{"v":1,"subdomain":"…","online":true|false}`；子域名格式不对 400 |
| 其他 | 404 / 405；按地址限频，超出 429 |

在线查询回答的只是“此刻有没有一条已登记的控制连接”。

## 8. 上限（运营方配置）

全部在配置文件的 `limits` 里，默认值见 `src/config.ts` 的 `DEFAULT_LIMITS`。“每个来源”指一个 IPv4 地址，或一个 IPv6 /64；IPv6 另按 /56（× `source56Factor`）和 /48（× `source48Factor`）合计。包括：公网端口总连接数、每个来源的连接数和新建速率、每个来源未登记的控制连接数和在线 Daisy 数、ClientHello 的大小和**绝对**时限（防慢速攻击）、中转自己域名的握手和请求头时限与限频、在线 Daisy 数、未登记的控制连接数、控制消息大小和速率、每个 Daisy 的流数（等待中和总数）、新流速率、认领时限、数据帧大小、每条流的总字节和空闲 / 总时长、每个 Daisy 的带宽、每条流每个方向的排队窗口、全中转排队总预算、关闭宽限。

## 9. 中转能看到什么、看不到什么

- 能看到：SNI（也就是目标的子域名）、调用方地址、每条流的字节数和时长、谁在线。
- 看不到：请求、回答、令牌、路径、HTTP 头；TLS 1.3 下连 Daisy 的证书也看不到。
- 限度（ADR-100、D-41 ②）：中转运营者控制 `D` 的 DNS 和 443，能为 `<子域名>.D` 申请受信任的证书并在中间解密。**第三方客户端**只靠 WebPKI，挡不住这种作恶的运营者；**Daisy 之间**的调用在发令牌前校验对方用身份私钥签的 TLS 绑定声明，中转产不出这份声明（P5-02 / a2a-usage）。中转自己的证书只能覆盖 `D`，不能是通配证书（`daisy-relay --check` 拒绝通配证书）。

## 10. 以后（不在版本 1）

- HTTP-01 质询的 80 端口按 `Host` 明文转发（ADR-100 A2，作为 TLS-ALPN-01 签不下来时的第二选择）：要在 `open` 里区分明文和 TLS，Daisy 一侧也要分开处理，留给以后的次版本。版本 1 的中转不监听 80。
- 一条连接上的多路复用（ADR-100 C2/C3）。
- 好记的别名。

次版本只增加字段和消息类型：两边都忽略不认识的字段和 `t`。改变已有含义时升主版本（新路径 `/v2/…`）。
