# 安全模型

[English](../en/security.md)

这一页说 Daisy 怎么守住主人的东西，以及它守不住什么。最后一节“已知限制”请一定读。

## 几条基本的事实

- **一个 Daisy 一位主人。** Daisy 以主人的系统账户运行，主人就是这个账户。没有多账号、没有管理员。想给别人用，让他装自己的 Daisy。
- **没有中心服务器。** 会话、设置、密钥都在主人机器的数据目录里，只有主人能读（0700 / 0600；Windows 上只有主人、SYSTEM、管理员）。Daisy 进程的文件创建掩码是 077，每次启动还会把数据目录里组或其他账户有权限的条目收紧（不跟随符号链接，只改属于你的）；`daisy doctor` 会报告还剩下的。AI 起的程序（harness、命令、终端）沿用启动 Daisy 时的掩码，因为它们在你自己的目录里写文件。
- **AI 也以主人的账户运行。** harness 起的进程能读主人能读的一切。这是下面很多设计的出发点，也是最大的限制。
- **安全排第一。** 没有互认的人进不来；任何授权都不包含对话记录、工作目录和凭据；放别人进来的决定只认主人本人加 PIN。
- **被打断的执行不重放。** 停止、重启、更新打断的一轮标为中断，不会自己再跑一遍。

## 两个入口面

| | 本机面 | 对外面 |
| --- | --- | --- |
| 监听 | 只听 `127.0.0.1`，永远开着 | 默认关；开启要 PIN；也可以只经中转开着 |
| 给谁 | 这台机器上的主人：网页、命令行、AI 的工作凭据 | 别的机器：主人的网页、配对设备、别的 Daisy、第三方 A2A 客户端 |
| 加密 | 不出本机 | 默认 TLS（自签名证书，浏览器里的 SHA-256 和 `daisy access show` 打印的一致再继续）；明文只允许回环、内网、组网地址 |
| 终端、执行命令、浏览目录 | 有 | 默认关，打开要 PIN；经中转一律关 |

每个连接被哪个监听器接受，就属于哪个面。检查只看这个标记，从不看来源地址或请求头。

每个请求都经过同一道集中检查，顺序是：

1. `Host` 必须是这个面自己的名字（防 DNS 重绑定）。
2. `/api` 请求带 `Origin` 的必须是这个面自己的源，`Sec-Fetch-Site` 只能是 `same-origin` 或 `none`（防跨站）。例外只有主人加进白名单的外部界面来源，且只在对外面上。
3. 接口定义表里没有的 `/api` 路由一律拒绝。
4. 认凭据。认不出就 401，不说是哪一条不对。
5. 按定义授权：对外面的开关、通道、AI 只限自己的会话、scope、PIN。

## 谁拿着什么凭据

| 谁 | 凭据 | 有效 | 在哪个面 |
| --- | --- | --- | --- |
| 命令行 | `keys/cli-credential`（0600） | 一直有效 | 只本机面 |
| 主人的网页 | 网页会话（`daisy open` 的一次性口令换来，口令 10 分钟、一次） | 本机面 30 天，对外面 7 天 | 只签发它的面 |
| 配对的设备 | 设备凭据，只用来换 12 小时的设备会话 | 30 天不用失效；可单独吊销 | 只配对时的面 |
| AI | 每一轮一张工作凭据（签名令牌） | 最多 1 小时，这一轮结束立即无效 | 只本机面 |
| 别的 Daisy | 对方用身份私钥每次现签的令牌 | 只能用一次 | 对外面的 A2A 入口 |
| 第三方 A2A 客户端 | `daisy token issue` 签的令牌 | 默认 7 天，最多 90 天 | 对外面的 A2A 入口 |
| 外部签发方 | 主人配置的签发方签的令牌 | 签给主人的最多 24 小时 | 两个面 |

服务端只存凭据的 SHA-256，不存凭据本身（命令行凭据文件 `keys/cli-credential` 除外：命令行要读它，所以存的是原文，只有你的账户能读）。AI 的工作凭据只能读自己会话的少数几条接口；它不能回答工具授权和提问，也不能做任何要 PIN 的事。

**网页口令。** 这台机器只有你一个账户、对外面也关着时，本机的浏览器可以不带口令打开网页（Daisy 核对连接另一端的进程属于你的账户）。机器上有别的账户、或者开了对外面时，口令自动生效：一律经 `daisy open` 的一次性链接。`daisy access passcode on|off|auto` 可以改（要 PIN）。

## PIN

PIN 守着“放别人进来”的每一种操作：

| 种类 | 例子 |
| --- | --- |
| 入口 | 开启对外面、对外面的一次性口令、本机网页的口令设置 |
| 中转 | 选择、停用中转 |
| 设备 | 配对新设备、吊销设备 |
| 互认 | 导入、移除名片，管理白名单 |
| 调用 | 批准或拒绝别人的调用请求、撤销授权、改开放范围 |
| agent | 把会话设为公开、设置是否允许“办”、创建和修改常驻 agent |
| 令牌 | 签发、吊销给第三方 A2A 客户端的令牌；配置外部签发方 |
| 外部界面 | 改允许的外部界面来源 |
| 更新 | 设置更新来源（它决定以后跑什么代码） |

- 至少 6 位，可以是纯数字。只存校验值（scrypt）。
- 输对一次得到一个短时的授权（5 分钟），绑定在发请求的凭据上。命令行的授权**用一次就作废**：所有命令行进程（包括 AI 经 shell 调的 `daisy`）共用一个持有者，不能让它借你刚输的 PIN。
- 网页、设备上读这类设置不要 PIN；本机命令行读也要（命令行凭据可能正被你的 AI 用着）。
- 连续输错 5 次锁 15 分钟，再 5 次锁 1 小时，之后翻倍，最长 24 小时。锁定存在数据库里，重启不清除。
- **没设 PIN 时，Daisy 不启动任何 AI 轮次。** 网页和配对设备上会一直显示 PIN 是什么时候、经哪个入口设置或重置的。

**重置 PIN**（`daisy pin reset --confirm`，只能在本机命令行做）收回一切放进来的东西：关闭对外面并作废它上面的会话和口令、停用中转、吊销所有授权、互认的名片、配对的设备和第三方令牌、作废替 AI 取来的令牌、清空允许的外部界面来源、撤销对外部签发方的信任。之后只能在本机命令行重新设置。公开的 agent 不会被收回私有，常驻 agent 也不会暂停，但名片、授权、令牌都没了，没人调得进来。

## 别人怎么调用你

1. **互认**：双方交换身份名片（`daisy contact export` / `daisy contact import`）。名片由身份私钥签名，但只证明“这段内容是这把钥匙的主人发的”。导入前请和对方当面或电话核对编号（至少前 16 个字符，`--expect-id`）。互认本身不带任何调用权限。
2. **agent 的种类**：会话默认是**私人** agent，谁也调不了。你可以把一个会话设为**公开**（别人直接在这个会话上“问”或“办”，会串话，见下），或者建一个**常驻** agent（每段来访对话有自己的会话，互不相见，权限按你的配置）。
3. **开放范围**：对所有互认的人开放，或只对指定的人。
4. **第一次调用**：对所有人开放的 agent，第一次调用弹一张卡片给你：永久通过、仅本次、拒绝。拒绝后 10 分钟内同一个人调用同一个 agent 直接拒绝。卡片 7 天没人处理就过期。白名单里的人不弹卡片。
5. **问与办**：别人默认只能“问”（只读地回答），带“办”的标记才动手，你可以关掉“办”。只读的强弱和走法见 [harness 支持范围 › 问与办](harnesses.md#问与办)。外来任务永远不用跳过所有确认的权限模式。
6. **交给 AI 时标明来源**：别人写的一切都作为外部资料交给 AI，标明来自谁、是问还是办，明说不是主人的指令。对方 AI 的回答对你的 AI 来说也只是参考资料。

授权的规则：粒度是每个 agent 乘每个人；单向；不传递；只含调用，不含对话记录、工作目录、凭据；随时可撤销（`daisy grant revoke`），撤销即停下他进行中的调用。

## 审计与脱敏

- 每个通过检查的改动、每个被拒绝的请求、每次 AI 的工具调用都记一条审计：谁、经哪个面和通道、哪条接口、结果、原因、链路号。不记查询串、请求体、凭据、PIN、口令。
- 看：`daisy audit list`（审计）、`daisy audit logs`（最近的日志行）。读审计本身也留痕。AI 读不了这两条。
- 脱敏：Daisy 制造或拿到的每个秘密（各种凭据、PIN 授权、harness 的 API key、登录授权码）一出现就登记，日志、错误回答、审计里出现时换成 `[redacted]`；另外按形状遮掉看起来像令牌、密钥、口令的串。宁可多遮。
- 日志只写到 `logs/daisy.log`（或 journald），最近 1000 行在内存里供 `daisy audit logs` 读。

## 中转的运营者能看到什么

- 能看到：目标的子域名、调用方地址、每条连接的字节数和时长、哪些 Daisy 在线。
- 看不到：请求、回答、令牌、路径、HTTP 头。
- 作恶的运营者能为你的子域名申请受信任的证书、在中间解密。Daisy 之间的调用核对 TLS 绑定声明，挡得住；第三方客户端和浏览器挡不住。详见 [中转 › 用别人运营的中转](relay.md#三用别人运营的中转)。

## 已知限制

这些不是缺陷，是设计时已经知道、写下来请你知道的事实。

1. **AI 读得到主人能读的一切。** 包括数据库、PIN 的校验值、身份私钥、命令行凭据。一个存心绕过的 AI 能直接改数据库或代码、离线猜 PIN（越短越好猜）、用私钥自签令牌。PIN 只挡“走接口”的路。被调用的一方那边仍有调用授权、撤销和并发上限兜底。
2. **给 AI 的窄权限在本机上只是约定。** AI 工作凭据的窄 scope、“工具授权只在网页上回答”，拦不住一个不守约的 AI。它也能改数据目录里的配置（例如 `config.json` 里的外部签发方、公钥缓存），重启后生效，不经 PIN。所以：只给你信得过的 harness 和模型自动权限；PIN 用长一点的。
3. **AI 可以故意输错 PIN**，把你暂时锁在“放别人进来”的操作之外。这只造成不便，不放任何人进来；锁定在网页上醒目显示。
4. **公开 agent 会串话。** 来访者读得到这个会话的上下文，回答里可能带出你自己的工作；带“办”的请求在你的主线上按自动模式动手，一问一答留在主线里。要互不干扰，用常驻 agent。
5. **常驻 agent 的隔离有缺口。** 各段来访对话是分开的会话，但共用这个 agent 的工作区：一段对话写进工作区的文件，另一段读得到。允许 Bash 时，shell 能读主人能读的文件，挡住别的对话的记录只能靠 harness 的禁读规则和自动模式的判断。对外人提供服务时，把它的工具收到只读（Read、Grep、Glob），或给它单独的工作区和身份档。网页上会提示。
6. **机器关了，上面的 AI 就联系不上，历史也看不了。** 中转不保存任何东西。
7. **ACP 接入的 harness 能力比原生的少**；Kimi Code、OpenCode 的“问”只是弱只读。见 [harness 支持范围](harnesses.md)。
8. **macOS、Windows 上没有 Daisy 自己的强制只读**，Windows 上 Codex 的“问”也只是弱只读。
9. **第三方客户端经别人的中转调用你，要信任中转运营者。** 经只有中转的链接配对设备时，运营者理论上能拿到配对码和设备凭据。
10. **吊销不回滚。** 吊销设备、收回授权、关掉“办”时，已经开始执行的改动不会撤销，正在跑的一轮跑完或被停下，副作用不回滚。
11. **手工换了中转的 TLS 密钥后，旧的 TLS 绑定声明在过期前（最多一天）仍然有效。** 正常续期不换密钥，不受影响。

## 报告安全问题

发现可以利用的问题时，请不要在公开的 issue、讨论或合并请求里贴细节。用 GitHub 的私密漏洞报告：在仓库的 **Security** 页点 **Report a vulnerability**（<https://github.com/QuantGrail/daisy/security/advisories/new>），只有你和维护者看得到。要写什么、范围和支持的版本，见仓库根目录的 [SECURITY.md](../../../SECURITY.md)。
