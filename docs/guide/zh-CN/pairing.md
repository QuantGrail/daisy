# 配对手机或另一台电脑的浏览器

[English](../en/pairing.md)

配对让另一台设备以主人的身份打开 Daisy 的网页：看会话、发消息、回答 AI 的工具授权和提问。手机上用浏览器，不需要装 App。

## 先让设备连得到这个 Daisy

配对码只在对外面上能用。二选一（都要 PIN）：

- **对外面直连**：设备和 Daisy 在同一个内网或组网里时用。

  ```sh
  daisy access external on --host <这台机器的组网或内网地址>
  ```

  默认用 TLS（自签名证书）。明文（`--tls false`）只允许回环、内网或组网地址。

- **经中转**：设备在别的网络里时用。见 [中转](relay.md)。

两个都开着时，配对链接默认用直连的，中转的另给。

## 生成配对码

```sh
daisy pair --name 我的手机
```

或者在网页的“设置 › 设备”里点“生成配对码”（要 PIN）。网页会显示大字的码、链接和二维码。

- 码是十位（`XXXXX-XXXXX`），10 分钟内有效，只能用一次。
- 链接是 `<对外面的地址>/#pair=<码>`。码在 `#` 后面，不进请求行和日志。
- 同时最多 5 个没用掉的码，再生成就挤掉最早的。
- 设置、修改或重置 PIN 之后，没用掉的码全部作废。

## 在设备上输入

用手机扫二维码，或在设备的浏览器里打开链接，页面会填好码；也可以打开对外面的地址，选“用配对码连接这台设备”，手动输入码和设备名。

对外面用自签名证书时，设备的浏览器会提示证书不受信任。先核对证书再继续：

1. 在 Daisy 所在的机器上运行 `daisy access show`，记下 `external.fingerprint`——对外面证书的 SHA-256 指纹（`AB:CD:…` 这样冒号分隔的 64 位十六进制）。`daisy pair`、`daisy status` 和网页“设置 › 入口面与口令”也会给出同一个。
2. 在设备的浏览器里查看证书详情（Chrome：地址栏左边的图标 › 证书），找到 **SHA-256** 指纹。
3. 两个一致才继续；不一致就停下，不要点过警告。

证书只在第一次开启、监听地址换成它不覆盖的、或快到期（397 天）时才换新的，每次都写进日志和审计（`access.tls.generate`，带原因和新指纹）。证书文件在但用不了（例如属主不对、密钥和证书不是一对）时，对外面开不起来并说明原因，不会悄悄换一张。换过证书后，已配对的设备和记住了旧证书的调用方会看到证书变了：用上面的办法重新核对。

配对成功后，设备拿到一份设备凭据，存在那个浏览器里。之后打开同一个地址就直接进来。

- 设备凭据 30 天不用就失效。
- 每次请求用的是设备会话，12 小时换一张，设备自己会换。
- 设备上“退出”就是取消这台设备的配对。

## 经中转配对时要注意

- 只有中转、没有直连时也能配对，但 `daisy pair` 会直接警告：**中转的运营者理论上能拿到配对码和设备凭据**（他能为你的中转地址申请证书、在中间解密，见 [中转 › 用别人运营的中转](relay.md#三用别人运营的中转)）。用自己架的中转就没有这个问题。
- 中转只有自签名证书（ACME 还没申请到）时，不给链接，只给码。在设备上手动输入码，并且**不要点过证书警告**。

## 管理设备

```sh
daisy device list               # 配对过的设备（只有记录，没有凭据）
daisy device revoke <设备 id>   # 吊销一台，要 PIN
```

网页的“设置 › 设备”能做同样的事。吊销立即生效：它的会话作废，已连上的实时通道马上断开，正在处理的请求回答 401。吊销前已经开始执行的改动不会撤销。

重置 PIN 时，所有配对的设备一起失效。

## 防猜

- 同一个来源输错 5 次，这个来源暂停 15 分钟，别的来源照常。
- 一个码发出之后，所有来源一共输错 20 次，这个码就作废。
- 码不对、过期、用过，回答都一样，不说是哪种。
- 能连到对外面的人可以故意输错，让你暂时配不了新设备。这只造成不便，不放任何人进来；审计里看得到。
