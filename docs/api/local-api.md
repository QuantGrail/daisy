# Local API

> This file is generated by `npm run gen:api` from the definitions in `packages/contracts/src/api/` — do not edit it by hand.
> A test (`tests/api-defs.test.ts`) checks that it matches the definitions. The mechanism is in ADR-107.

API version: 1. 172 routes: 135 have a command, 37 say why they have none.

Scope, channels and PIN are the annotations of `docs/contracts/scopes.md`, checked by the server against the definitions. By default the channels are the owner's four (the web page, a paired device, the command line, a token the external issuer signed for the owner); a token the external issuer signed for someone else can never call the local API (only the A2A entry); an AI's working credential can only call routes marked “AI (own session only)”. The AI's own tools (`daisy:tools`: timed wake-ups, recurring tasks, background commands, speaking up) are offered over MCP, not the local API, and are not in this table; the one exception is fetching a token for the AI (`session.aiToken`), which the MCP inside the harness calls with the turn's AI working credential.

<a id="session-aitoken"></a>

### session.aiToken

`POST /api/sessions/:id/ai-token` — Get a token on behalf of this AI (for an MCP in the harness that needs one)

Callable only with the current turn's AI work credential (`DAISY_AI_CREDENTIAL_FILE`), so it is available only while a turn is in progress. The token names the owner (sub) and the AI actually acting (act), its scope never exceeds the owner's, and it is valid for at most 1 hour; for the same session, audience and scope, the same token is given back while more than 5 minutes remain (even across turns), otherwise a new one is obtained; each session keeps at most 16 tokens and may obtain at most 10 new ones per minute (beyond that it answers 429). In external mode it performs an RFC 8693 token exchange with the external issuer; in standalone mode this Daisy signs it itself.

| `daisy:tools` | — | AI (only when `:id` is its own session) | — | none: For the AI's own use: an MCP in the harness calls it with the current turn's AI work credential; the owner and the command line do not need to get tokens on the AI's behalf |

> Does not let anyone in: Gets a token for this turn's AI to access other systems (daisy:tools, without daisy:grant, ≤ 1 hour); lets nobody into this Daisy.

### grant.publicSet

### settings.pair

`POST /api/devices/pair` — Make a pairing code (daisy pair): another device that enters it connects as the owner

A kind of "letting someone in" (kind device): needs the PIN; the AI cannot do it. <a id="events-list"></a>

### events.list

`GET /api/events` — Read the event outlet incrementally by sequence number (long polling supported)

Each event is a CloudEvents 1.0 event (docs/contracts/events.md): an AI asking for approval, an AI asking a question, someone's call waiting for approval — each with an "opened" and a "resolved" kind. Ordered by `seq`, ascending; `cursor` is the last event's `seq` on this page (equal to `after` when the page is empty), to pass as `after` next time; when `hasMore` is true, read on at once.

With no new event within `wait` seconds (at most 30) the answer is an empty page; a new event is answered at once.

Resuming after a disconnect: a subscriber saves `cursor` after it has handled a page and reads on from it after a restart; it may read the same batch again — deduplicate by `id`. An `after` older than the events still kept (already cleaned up), or larger than the highest sequence number this Daisy has written (its data was rebuilt), answers 410 with `code: cursor_reset`: take a snapshot first, then read on from the snapshot's `cursor`.

With nobody subscribed nothing happens: events are written all the same and cleaned up after 30 days; an "opened" event of a card not yet resolved is kept until it is resolved.

| scope | PIN | Channels | Idempotency key | Command |
| --- | --- | --- | --- | --- |
| `daisy:events:read` | — | web page, paired device, command line, a token the external issuer signed for the owner | — | `daisy events list` |

**Query parameters**

| Field | Type | Required | Limits | Description |
| --- | --- | --- | --- | --- |
| `after` | integer |  | ≥ 0 | Answer only events whose seq is greater than this (the cursor from the last answer), default 0 |
| `limit` | integer |  | 1–200 | How many at most; default 200 |
| `wait` | integer |  | 0–30 | Long poll: with no new events, wait at most this many seconds (0–30); a new event is answered at once |

**Answer**: JSON, `EventsPage { events: DaisyEvent[], cursor, hasMore }`

**Error codes**: `cursor_reset`

```text
Usage: daisy access external on [options]

Turn on or change the outside face (listen address, port, TLS, switches such as the terminal)

Widens who can connect, so it needs the PIN. Turning it on enables the passcode automatically. Plain HTTP is allowed only on loopback, overlay network or private network addresses (127/8, 10/8, 172.16/12, 192.168/16, 100.64/10, ::1, fc00::/7). TLS uses the self-signed certificate in keys/: a new one is generated only when there is none yet, when it does not cover the listen address, or when it expires within a day (written to the log and the audit); when the certificate files exist but cannot be used (wrong owner, key and certificate not a pair, unreadable), it answers 409 `tls_refused` and does not quietly replace the certificate.

Options:
  --host                   Listen address: overlay network address, 0.0.0.0, loopback address (for other programs on the same machine to visit), etc.; do not write localhost (string, 1–253 characters, required)
  --port                   Port; if empty, derived from the uid (from 29600) (integer, 1024–65535)
  --tls                    TLS by default (self-signed certificate); false (plain HTTP) is allowed only on loopback, overlay network or private network addresses (boolean, default true)
  --allow                  Open the terminal, command execution and directory browsing on the outside face (all off by default) (object, default {"terminal":false,"shell":false,"browse":false})

This step asks for the PIN (prompted in the terminal).

API: PUT /api/access/external (settings.externalOn)
```

```text
Usage: daisy access issuer refresh

Fetch the external issuer's key set again now

Normally fetched automatically according to the cache headers (every hour if there are none), and also on an unknown kid; use this after the issuer rotates its keys if you want that to take effect immediately.

API: POST /api/access/issuer/refresh (settings.issuerRefresh)
```

```text
Usage: daisy access issuer remove

Stop trusting the external issuer and go back to self-issuing

Narrows who can connect, no PIN needed (like turning off the outside face). The cached public keys and the owner's token are deleted too, and tokens obtained for the AI are no longer renewed.

API: DELETE /api/access/issuer (settings.issuerRemove)
```

```text
Usage: daisy access issuer set [options]

Configure an external issuer (trust the tokens it signs)

A kind of "letting someone in": from then on, tokens the issuer signs for the owner get the owner's identity (no pairing needed), and tokens signed for anyone else can only use the A2A entry. Needs the PIN, and the AI cannot do it. When configuring, the metadata and key set are fetched once, and nothing is saved if they cannot be fetched; after that, verification is offline, with key rotation by kid.

Options:
  --issuer                 The issuer identifier; must equal the iss of the tokens it signs: an https address (http only on this machine's loopback 127.0.0.1 / [::1], with DAISY_ALLOW_HTTP_ISSUER=1 set and no other people's accounts on this machine — for tests and local deployments) (string, 8–2048 characters, required)
  --metadata-url           Metadata address (RFC 8414 / OpenID Connect Discovery); derived from the issuer identifier when left out: an https address (http only on this machine's loopback 127.0.0.1 / [::1], with DAISY_ALLOW_HTTP_ISSUER=1 set and no other people's accounts on this machine — for tests and local deployments) (string, 8–2048 characters)
  --jwks-uri               Public key set (JWKS) address; taken from the metadata when left out: an https address (http only on this machine's loopback 127.0.0.1 / [::1], with DAISY_ALLOW_HTTP_ISSUER=1 set and no other people's accounts on this machine — for tests and local deployments) (string, 8–2048 characters)
```
