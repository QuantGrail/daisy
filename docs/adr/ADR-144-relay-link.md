# ADR-144：Daisy 的中转连接——只进对外面、TLS 绑定声明、ACME TLS-ALPN-01

- 日期：2026-11-18
- 状态：**已实施（P5-02，分支 `p5-02`，基于 `p5-01`（含审查后的修订，协议 1.1）；未合入 `daisy-next`）**
- 工作包：P5-02（Daisy 的中转连接）
- 相关：设计要求（`daisy relay` 选择和停用中转都要 PIN；中转重启后 30 秒内重连）；安全工作包；ADR-099（密钥与存放）、ADR-100（中转协议与端到端加密：B1/B2、TLS 绑定声明、作恶中转模拟）、ADR-101（中转进来的只进对外面）、ADR-102（数据目录）、ADR-121（PIN）、ADR-127（P4-08 客户端）、ADR-128（独立 MCP）、ADR-143 与 `packages/relay/PROTOCOL.md` 1.1（中转程序）

## 背景

P5-01 做好了中转程序：按 SNI 透传 TLS，控制 WebSocket + 每个外来连接反连一条数据 WebSocket，不在线在握手阶段拒绝。这个工作包做 Daisy 这一侧：选中转、连出并保持、断线自动重连、`daisy status` 显示，把中转地址写进名片，把经中转进来的字节流只交给对外面，为中转地址拿证书（ACME TLS-ALPN-01，拿不到用自签名），并落实 ADR-100 的 TLS 绑定声明，让 Daisy 客户端在发令牌之前核对它。

## 决定

### 1. 设置与接口

- `config.json` 的 `relay` 一节：`{ enabled, url, acme: { enabled, directory } }`（`packages/daisy/src/relay/config.ts`，读不懂一律当关闭）。
- `PUT /api/relay`（`daisy relay set <地址>`，`letsIn: "relay"`：`daisy:grant` + PIN，AI 的工作凭据不能做）；`GET /api/relay`（`daisy relay show`，`daisy:manage`）；`DELETE /api/relay`（`daisy relay off`）。
- **停用也要 PIN**：设计要求写的是“选择和停用要 PIN”，scopes.md 也是。它只收窄谁能连进来（定义里写 `notLetIn`），但命令行凭据可能是主人的 AI 经 Bash 在用，不该让它悄悄断开主人在别的网络里的可达性。（关闭对外面不要 PIN，两者不一致，见“待维护者确认”②。）
- 中转地址只认域名（`https`，可带端口，不带路径；IP 字面量一律拒绝——URL 解析会把 `127.1` 变成 IP，按解析后的判断）。
- 重置 PIN：中转随对外面一起关闭（`external-face` 那一类的另一个钩子）：先同步写“已停用”（写不进就让重置失败，不谎报），无论写没写成都立即断开（审查 L-2），对外面的网页会话作废。

### 2. 连接（`relay/link.ts`，PROTOCOL.md 1.1）

- 连 `wss://<域名>[:端口]/v1/control`，用身份私钥签挑战（`SelfIssuer.signRelayProof`，头恰好 `{"alg":"EdDSA","typ":"daisy-relay-proof+jwt"}`）；收到 `welcome` 先核对 `id` 等于自己的身份编号、`host` 等于 `<前 32 个字符>.<域名>`，不对就断开。
- 重连：`基数 × 2^次数`，上限 30 秒，乘 0.5–1；登记成功清零；1012（中转重启）从基数重来；4409（同一把钥匙在别处连上）退到上限，不互相顶；**4403（运营方允许名单不收）不再重试**，状态 `refused`，`daisy status` 说明；429 / 503 / 4503 照常退避并给出可读的原因。
- 心跳：超过 2.5 × `pingIntervalMs`（welcome 给出，默认 20 秒）没收到 ping 就自己断开重连。
- 外来连接：每个 `open` 开一条数据连接，**认领凭据放在升级请求头 `daisy-relay-claim`**（协议 1.1；只在 `openDataStream` 这一个函数里），不带 `Origin`；发出的每一帧不超过 `maxDataFrameBytes`（默认 64 KiB，更大的写拆开）。同时处理的流超过 64 条就在控制连接上 `reject`。`claim`、`nonce`、`proof` 不写日志。

### 3. 只进对外面（ADR-101）

- **是否要先开对外面？不要。** 选了中转，对外面就“经中转开着”：中转的字节流进 `Faces` 里一个**不监听任何端口**的 TLS 服务端（`injectRelay`），它打 `external` 标签、把请求交给同一个路由，所以对外面的全部规则照用：只认对外面的凭据（本机命令行凭据、AI 工作凭据、本机网页会话一律不认）、终端 / 执行命令 / 浏览目录的开关、Host 与 Origin 检查（中转地址加进对外面的名字）、口令自动启用（`passcodeOn` 把中转算作对外可达）。理由：阶段 5 的完成标准是“路由器后面的电脑选一个中转就能被调用”，不该还要主人去设一个没用的监听地址。
- 中转模块只拿到 `injectRelay` 这一个函数，碰不到本机面的服务对象；那个 TLS 服务端只持有中转地址的证书，SNI 不是中转地址就握手失败。
- 握手之前先读 ClientHello（`relay/hello.ts`）：ALPN 是 `acme-tls/1` 的是证书机构的 TLS-ALPN-01 检查，交给一个只出示质询证书、握完就关的小 TLS 服务端（只在有质询时），**永远到不了对外面**；其余进对外面。
- 调用方的地址（中转在 `open` 里报的，只收 IP 字符）放在这条连接自己的标记里（`VIA_RELAY`），**从不写进 `remoteAddress`**；限频的键按面分开，经中转的按 `relay:<地址>` 计（审查 M-1：原来写进 `remoteAddress`，中转报一个 127.0.0.1 就能把本机面的口令登录额度用光）。取地址依赖 Node 把非套接字的流包进内部 JSStreamSocket 的结构（`_handle._parentWrap.stream`），取不到时经中转的调用方共用一个键——仍不碰本机面的。
- **经中转不提供终端、执行命令、浏览目录（审查 L-3，调度决定：默认关）**：不管对外面自己的开关怎么设（那是主人为一个自己选的监听地址开的，不是为任何能连到中转的人），经中转的这几类路由一律 403 `external_off`。以后若要经中转提供，加单独的、要 PIN 的开关。停用中转时对外面的网页会话一并作废（同关闭对外面）。

### 4. 名片

- 选了中转（不论此刻连没连上——地址是固定的），默认导出的身份名片 `addrs` 带 `{ kind: "relay", url: "https://<身份编号前 32 个字符>.<中转域名>[:端口]" }`；停用后不再带。
- agent 名片的接口地址取请求到达的地址（P4-04），经中转来就是中转地址；停用后中转地址不再是这个 Daisy 的名字（Host 检查拒绝）。
- 契约修正：identity-card.md 第 3 节原来写“52 个字符的身份编号可以直接当子域名”，与 ADR-100 和中转协议不一致，改为“前 32 个字符”；`packages/a2a-client/src/identity.ts` 的注释表同改。

### 5. 证书（ADR-100 B1/B2，`relay/certs.ts`、`relay/acme.ts`、`relay/x509.ts`）

- 中转地址用一把单独的 **ECDSA P-256** 密钥（`keys/relay-tls-key.pem`，0600），续期和换中转都复用；ACME 账户另有一把 ECDSA P-256 密钥（`keys/acme-account-key.pem`）；状态在 `keys/relay-tls.json`。
- 选了中转立即生成自签名证书（马上能在 Daisy 之间用），ACME 在后台申请，成功就换上；失败保留现有证书，1 小时后再试、每次翻倍、最多 24 小时（照顾 Let's Encrypt 的“每小时 5 次验证失败”）。
- ACME 目录可配置（默认 Let's Encrypt），可以关掉（只用自签名）。打开 ACME 即同意该 CA 的订户协议（`termsOfServiceAgreed`），界面写明。
- 续期：CA 有 ARI（RFC 9773）就按它给的窗口里随机一刻续，订单带 `replaces`；没有就在剩三分之一寿命时续；每 6 小时看一次。
- 保留域名（`.test`、`.example`、`.invalid`、`.localhost`、`.local`、`.internal`、`home.arpa`）**不管哪个 ACME 目录都不申请**（审查 L-4；只有测试里进程内的 ACME 替身经一个测试专用开关可以），状态里写明。
- 账户密钥文件坏了或权限太松：状态里显示原因、稍后再试，不会让 Daisy 崩（审查 L-1）；停用或换中转时，正在进行的申请一并中止。（施工中一次测试曾因地址校验漏了 IP 而真的连到了 Let's Encrypt，见“施工记录”；这条和 IP 拒绝一起堵上了。）
- **没用 `acme-client`**（ADR-099 写的是它）：它把 axios 和 @peculiar/x509 连同十几个间接依赖带进安全包，5.4.0 没有 ARI，要信任测试 CA 得改全局设置。这里自己只写了 RFC 8555 的消息流程（约 300 行）：JWS 用 `jose`（ES256），签名一律 `node:crypto`，证书和 CSR 的 DER 结构用 node-forge 的 ASN.1 编码器拼（node-forge 只能签 RSA，node:crypto 不能写证书）。服务器给的每个地址必须和目录同源。没有新增依赖。（见“待维护者确认”③。）

### 6. TLS 绑定声明（ADR-100，a2a-usage.md 第 15.1 节）

- 服务端：`GET /.well-known/daisy-tls-binding`（公开，两个面都有），身份私钥签的 JWS，头恰好 `{"alg":"EdDSA","typ":"daisy-tls-binding+jwt"}`，载荷 `{ v: 1, id, spki: [...], iat, exp }`；`spki` 是中转密钥和对外面直连密钥（有的话）的 SPKI SHA-256（base64url）；每小时重签，有效一天。
- 客户端（`packages/a2a-client/src/binding.ts`，Daisy 和独立 MCP 共用）：对 `relay` 地址的每一条要带令牌的连接，握手后**先不写任何字节**，用联系人在通讯录里的公钥核对声明（缓存到 `exp`；不认识的 SPKI 再取一次），声明里有这条连接证书的 SPKI 才发请求。CA 签没签不算数（作恶的中转能让 CA 签）。不对：断开、什么都不发、这次调用以拒绝结束、审计 `a2a.tls.binding_refused`（`tls_binding_mismatch` / `tls_binding_invalid`）。没有对方公钥的客户端不连 `relay` 地址（失败即拒绝）。
- `direct` 地址照旧（CA 证书，或自签证书首次信任并钉住，P4-08）。
- 限度：主人手工换了中转 TLS 密钥后，旧声明（列着旧密钥）在过期前（最多一天，客户端最多接受 7 天）仍然有效；旧密钥若是因为泄露才换的，要等旧声明过期，期间持旧密钥的人仍能冒充。正常续期不换密钥，不受影响。

### 7. `daisy status`

多一行“中转”：已连上 / 正在连接 / 没连上（几秒后重试和原因）/ 被中转拒绝，对外地址，证书种类——自签名时写“经中转只有 Daisy 之间能用”，ACME 没申请到时附原因。设置页“入口面与口令”下加“中转”一节（选择、停用都要 PIN）。

## 真机检查

两个 Daisy 在两个互相连不通的网络里、连到同一个中转，互相调用成功。这一项要在真机上做，不在本文的自动测试里。

## 施工记录（如实写）

- 第一版地址校验把 `https://127.0.0.1` 当成了域名，那条“地址不对就 400”的测试反而让它通过了；同一条测试没写 `acme: false`，ACME 默认开着，于是**测试进程真的向 Let's Encrypt 发了一次注册账户和一次下单**（被 LE 以“不是合法域名”拒绝，没有签出任何东西；账户密钥在临时目录里，已随测试删除）。已修：IP 字面量（含 URL 解析后变成 IP 的写法）一律拒绝；保留域名配默认目录时不申请；所有测试都用 `acme: false` 或进程内 ACME 替身。

## 待维护者确认

1. **选了中转就算对外面开着，不需要先开对外面的监听**（第 3 节）。口令随之启用；终端等开关按对外面的设置。
2. **停用中转要 PIN**（按设计要求和 scopes.md），而关闭对外面不要 PIN。要不要统一？推荐保持：停用中转是 AI 能拿来让主人“失联”的操作。
3. **不用 `acme-client`，自写 RFC 8555 流程**（第 5 节；没有新依赖）。
4. **默认 Let's Encrypt，打开 ACME 即同意其订户协议**；保留域名不申请。
5. 绑定声明对 `direct` 地址暂不强制（仍是 P4-08 的首次信任钉住）。以后可以在声明可用时也用它，消掉首次信任的那一下。
6. 经中转进来的“调用方地址”只是中转的一面之词，只用于按地址限频。

## 交给 P5-03（配对、手机经中转打开网页）

- 中转地址已经是对外面的一个名字：Host / Origin 检查接受 `https://<子域名>.<域名>[:端口]`，经它的请求按对外面处理，设备凭据（P5-03）放进对外面认的凭据即可经中转用。
- `daisy open --external`（`openCodeExternal`）现在只在对外面**监听**时可用，链接用直连地址；只经中转时要改成用 `relay.address()`（`ctx.relay.address()`）生成链接，并把“对外面可达”改用 `faces.externalReachable`。
- 手机浏览器要受信任证书：ACME 成功（`cert.kind === "acme"`）时才能经中转打开网页；自签名时浏览器报警，界面要说明（ADR-100）。
- Cookie 若引入，按 ADR-100 一律 `__Host-` 前缀。

### P5-03b 审查 M-1：作恶中转的限度延伸到主人身份（2026-11-18）

ADR-100 与维护者的决定写明的限度是：中转运营者掌握中转地址的 DNS 和 SNI，能自己回答 ACME 的 TLS-ALPN-01、拿到公共 CA 给中转地址签的证书，在中间终止 TLS；后果写的是“第三方 A2A 客户端（不核对 TLS 绑定声明的）可能被骗”。P5-03b 让手机浏览器经中转打开网页、配对，后果因此**延伸到主人身份**：经中转打开的页面上，运营者能读到 `#pair=` 后的配对码、该来源 `localStorage` 里的设备凭据（`ddev_`，长期以主人身份连进来）、`daisy open --external` 的一次性口令和它换到的网页会话。浏览器不核对 TLS 绑定声明，Daisy 之间的那道保护在这里没有。

决定（调度定的安全默认，维护者可以改，见 ADR-142“经中转（P5-03b）”第 2 条与“待维护者决定的问题”第 6 条）：对外面的监听开着时，配对链接和 `open --external` 的链接默认直连，中转的链接只作另一个选择；只有中转时照发，但处处直说运营者能拿到配对码和设备凭据、只在信任这个中转（例如团队自己架的）时用；中转只有自签名证书时不给经中转的链接。以后的缓解：**证书透明度（CT）监控**——定期查 CT 日志里中转地址的证书，出现 SPKI 不在自己 TLS 绑定声明里的证书就告警并停发经中转的链接（没做）。另：非 Let's Encrypt 目录签的证书在配对链接里报 `custom-ca`（手机要信任那个 CA），ACME 回来的证书不是给这个主机名的叶子就当自签名（`relay/certs.ts` `acmeLeafOk`）。
