# ADR-101：两个入口面——本机面与对外面

- 日期：2026-11-16
- 状态：**已确认**（2026-11-17，维护者的决定）：按推荐
- 工作包：P0-05 第 3 项（设计里“分成本机面和对外面两个入口”的建议）
- 相关：P1-03、P2-04、P4-04、P5-02、P5-03；ADR-099、ADR-100、ADR-102

## 背景

Daisy 既要“默认别的机器连不进来”，又要“可以被别人调用”（直连或经中转）。设计建议分成两个入口面：

- 本机面：只监听回环地址，给本地网页和命令行用。
- 对外面：默认关闭，主人开启（要 PIN）后才监听，提供 A2A 服务端，以及给已配对设备或外部签发方令牌用的主人接口；所有请求带令牌；中转进来的请求只进对外面。

现状：现在是一个 Fastify 实例监听 `HOST:PORT`（默认 8787），靠 `network.ts` 按内网地址准入、靠账号令牌区分身份。这些在单主人之后都要删。

还有一处要对齐：P1-03 写“主人可以把监听范围设到组网地址上，成员就从自己的电脑用浏览器直接打开”。如果这是“把本机面扩到组网地址”，就和“本机面只监听回环”矛盾。

## 可选方案

### A. 两个面怎么实现

| 方案 | 后果 |
| --- | --- |
| **A1. 同一进程里两个 HTTP 服务（两个 Fastify 实例），各自注册自己的路由，各自监听**：本机面 `127.0.0.1` 和 `::1`；对外面监听主人配置的地址，默认不监听 | 最清楚：对外面上**根本不存在**本机专用的路由，不是“存在但拒绝”。中转递进来的字节流直接注入对外面的服务对象（`server.emit("connection", socket)` 或把它包成 TLS 套接字后再注入），本机面永远收不到。两套路由要从同一份接口定义生成（P1-06），按“面”打标签，避免两边手写走样 |
| A2. 一个监听，按来源地址、`Host` 头或令牌类型区分 | 代码少，但“经中转进来的请求”在进程内往往表现为来自 `127.0.0.1`（反向隧道连本机端口的老问题，很多工具在这里出过事），一旦按来源地址判断就可能把外面的人当成本机。排除 |
| A3. 本机面改用 Unix 套接字 / Windows 命名管道（文件权限只给主人），对外面用 TCP | 命令行走套接字时，同一主机的其他账户连都连不上，比回环 TCP 更强。但浏览器不能连 Unix 套接字，本机网页还得走回环 TCP，等于三个监听；Windows 命名管道的权限又是一套。可以作为以后对命令行的加固，不作为这一次的结构 |

### B. 组网地址上的主人网页（P1-03；阶段 1 假设机器之间已组网、互相可达）放在哪个面

| 方案 | 后果 |
| --- | --- |
| B1. 本机面可以扩展监听到组网地址（P1-03 的字面意思） | 阶段 1 少做一个面。但“本机面只在回环上”这条不变量没了：本机面上有命令行凭据、AI 工作凭据能用的接口，扩到组网地址后它们都能从网络上被尝试；“别的机器连不上”变成只在“默认配置下”才成立 |
| **B2. 本机面永远只在回环上；从别的机器打开主人网页，走对外面**。阶段 1 先做对外面的“主人部分”（网页 + 口令登录），阶段 4 在对外面上加 A2A，阶段 5 加中转注入和设备配对 | 不变量干净：凡是来自网络的，都只能进对外面，对外面只认能离开本机的那几类凭据。阶段 1 要早一点把对外面的骨架搭起来（工作量不大：一个监听 + 主人网页 + 口令）。P1-03 的“改监听范围”就是“开启对外面并设置它的监听地址”，要 PIN，口令自动启用（本地网页的口令在监听超出本机时启用） |

## 推荐

**A1 + B2。** 具体如下。

### 监听

| | 本机面 | 对外面 |
| --- | --- | --- |
| 默认 | 开 | **关** |
| 地址 | `127.0.0.1` 和 `::1`，不可配置 | 主人配置：组网地址、`0.0.0.0` 等；开启和改地址要 PIN |
| 端口 | 见 ADR-102 | 见 ADR-102（与本机面不同） |
| 传输 | 明文 HTTP | 默认 TLS（有 CA 证书用 CA 证书，否则自签名 + TLS 绑定声明，ADR-100）；主人可以对“只在组网地址上”的监听选择明文（组网本身已加密，例如 WireGuard 类组网），选择时界面写明后果 |
| 中转 | 永远不接 | 中转递来的连接只注入这里（P5-02） |

### 哪些路由在哪个面

| 路由组 | 本机面 | 对外面 |
| --- | --- | --- |
| 本地网页的静态文件 | ✓ | ✓（主人从别的机器、手机打开） |
| 会话、审批、身份档、工作区、设置、附件（主人接口） | ✓ | ✓，只认主人身份（配对设备、网页口令登录、外部签发方签给主人的令牌） |
| 终端、执行命令、浏览本机目录 | ✓ | 默认**不提供**；主人可以开启（要 PIN）。见问题 3 |
| AI 自用的工具（`daisy:tools`） | ✓（AI 工作凭据只在这里有效） | ✗，路由不存在 |
| 回答工具授权与提问 | ✓（只认网页会话，不认命令行凭据，P1-03） | ✓（配对设备、网页会话） |
| “放别人进来”（`daisy:grant`，要 PIN） | ✓ | ✓（主人身份 + PIN） |
| A2A 服务端：agent 名片、发消息、查任务、取消（两种传输：HTTP+JSON 和 JSON-RPC） | ✗（同一主机上别的 Daisy 也走对外面） | ✓ |
| 身份名片、TLS 绑定声明（ADR-100） | ✗ | ✓ |
| 事件出口 | ✓ | ✓（带令牌的外部订阅方，P2-03） |

### 每个面认哪些凭据

| 凭据（ADR-099） | 本机面 | 对外面 |
| --- | --- | --- |
| 命令行的本机凭据 | ✓ | ✗ |
| AI 工作凭据 | ✓（只限 AI 工具和自己的会话） | ✗ |
| 本机网页会话（`daisy open` 的一次性口令换来的） | ✓ | ✗（各面的会话 Cookie 互不通用） |
| 对外面的网页会话（口令登录） | ✗ | ✓ |
| 设备凭据 | ✗（本机不需要） | ✓ |
| 外部签发方的令牌 | ✓（主人） | ✓（主人 → 主人接口；别人 → 只进 A2A） |
| 别的 Daisy 签的调用令牌、`daisy token` 生成的令牌 | ✗ | ✓，只进 A2A |

令牌里写明它是哪一类（契约 P0-04 定字段），每个面在路由层面先按“这个面认不认这类凭据”过滤，再做 scope 和授权检查。

### 两个面都要的防护

- **防 DNS 重绑定**：本机面只接受 `Host` 为 `127.0.0.1:端口`、`[::1]:端口`、`localhost:端口` 的请求；对外面只接受主人配置的主机名和地址。这是本地网页“防跨站”那一层的一部分，始终开启。
- **防跨站**：有 `Origin` 的请求，`Origin` 必须是这个面自己的源；网页的 Cookie 用 `SameSite=Strict`，对外面用 `__Host-` 前缀（ADR-100）。
- 对外面的速率和并发上限、请求大小上限集中成配置（所有时限和上限集中成一处配置）。

### 怎么保证中转进来的请求只到对外面

1. 中转连接模块只持有对外面服务对象的引用，拿不到本机面的。这一条用依赖结构保证（ADR-103：本机面的模块不导出给中转模块）。
2. 本机面只在回环上监听；中转注入的连接不经过任何监听端口，所以不存在“隧道连到本机端口”的路径。
3. 行为测试（先写“被拒绝”的）：经中转（测试里用假中转）对本机面才有的每一条路由发请求，都得到 404；用命令行凭据和 AI 工作凭据经对外面访问，一律 401。

## 对工作包的影响

- **P1-03**：“改监听范围”改写成“开启对外面、设置它的地址”，要 PIN，口令自动启用。阶段 1 的对外面只有：网页静态文件、主人接口、口令登录。“默认配置下别的机器连不上”的说法不变（默认只有本机面）。
- **P1-06**：接口定义里每条路由标明它在哪个面、认哪些凭据；路由注册、命令行、文档都从这份生成。
- **P1-08**：同一套网页在两个面上都能用；会话 Cookie 分面。
- **P2-04**：外部界面带令牌连进来，走对外面。
- **P4-04**：A2A 只注册在对外面；同一主机上两个 Daisy 互调，被调用方要开对外面（可以只监听回环地址）。验收里“同一台机器上起两三个 Daisy 互相调用”照此搭。
- **P5-02**：中转注入点是对外面的 TLS 服务端。
- **P5-03**：配对设备的凭据只在对外面有效。
- 删除 `network.ts` 的按地址准入。

## 待维护者决定的问题（已答复：按推荐；终端、执行命令、浏览目录在对外面上默认关、开启要 PIN）

1. **同意“本机面永远只在回环上，从别的机器打开主人网页一律走对外面”（B2）吗？** 这会把 P1-03 里“把监听范围设到组网地址”的含义改成“开启对外面”。推荐同意：不变量更简单，代价是阶段 1 早一点搭对外面的骨架。
2. **对外面在组网地址上可以选明文 HTTP 吗？** 推荐可以，但默认 TLS；选明文时界面提示“只在组网本身已加密时这样做”。代价：明文下浏览器不把它当安全来源（P1-03 已提到的那个问题），而默认 TLS 用自签名证书时浏览器又会报警，阶段 1 两样都要在 P1-08 里试。
3. **终端、执行命令、浏览目录这几样要不要默认在对外面上提供？** 权限设计写的是主人本人在配对设备上都能做。推荐对外面上默认关、主人开启要 PIN：这几样一旦凭据泄露，后果等于把机器交出去。
