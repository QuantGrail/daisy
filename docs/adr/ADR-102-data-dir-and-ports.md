# ADR-102：数据目录与端口

- 日期：2026-11-16
- 状态：**已确认**（2026-11-17，维护者的决定）：按推荐
- 工作包：P0-05 第 4 项（阶段 1 开工的前置条件）
- 相关：P1-03（端口不能写死）、P1-04、P1-07、P1-09、P5-04、P5-05；ADR-099、ADR-101、ADR-104

## 背景

- 现状：服务端的数据在源码目录下的 `.data`（`HARBOR_DATA` 可改），端口默认 8787（`PORT` 可改）；Runner 自动更新的东西在 `~/.local/share/agent-harbor/runner`。
- Daisy 是装给每个人的程序，数据要放在主人的目录下，不能在源码目录里。
- PyPI 上的 `daisy-sdk` 也装出一个 `daisy` 命令，把配置放在 `~/.daisy/`，所以不能用 `~/.daisy`。
- 团队的 Daisy 多数装在多人共用的 Linux 服务器上，同一主机有多个 Daisy，各属不同系统账户，端口不能写死（P1-03）。
- 8787 是 RStudio Server 的默认端口，在共用的数据分析服务器上很常见；IANA 上它登记给了一个旧的 Message Server。不宜继续当默认值。

## 可选方案

### A. 数据目录的位置

| 方案 | Linux | macOS | Windows | 后果 |
| --- | --- | --- | --- | --- |
| **A1. 各系统的惯例** | `$XDG_DATA_HOME/daisy`，未设时 `~/.local/share/daisy` | `~/Library/Application Support/Daisy` | `%LOCALAPPDATA%\Daisy` | 符合各系统习惯，备份工具、清理工具、系统迁移助手按惯例处理；与 `~/.daisy` 不冲突。文档要分系统写三个路径（`daisy status` 和 `daisy doctor` 直接打印实际路径，可以抵消） |
| A2. 统一的家目录点目录，例如 `~/.daisy-agent` | 同左 | 同左 | `%USERPROFILE%\.daisy-agent` | 三个系统一个说法，好找好写文档。但不合 macOS、Windows 的惯例；Windows 上家目录下的点目录会被一些同步工具（OneDrive 的“文档”重定向不涉及它，但企业的漫游配置可能涉及）带走 |
| A3. XDG 拆成三处：配置 `~/.config/daisy`、数据 `~/.local/share/daisy`、状态 `~/.local/state/daisy` | 三处 | — | — | 最“正宗”的 XDG，但违背“小而可删”原则里的“一个数据目录”，卸载、备份、迁移都要提三处 |

Windows 选 `%LOCALAPPDATA%` 而不是 `%APPDATA%`（漫游）：数据库、私钥不应该随漫游配置同步到别的机器，也不适合放进漫游同步的体积。

### B. 运行时文件（端口、进程号）放在哪

| 方案 | 后果 |
| --- | --- |
| **B1. Linux 上有 `$XDG_RUNTIME_DIR` 时放 `$XDG_RUNTIME_DIR/daisy/`（每个用户自己的 tmpfs，0700，注销即清），否则放数据目录下的 `run/`；macOS、Windows 放数据目录下的 `run/`** | 重启机器后不会留下过期的运行时文件（Linux）；其他系统靠“进程号是否还活着”判断过期 |
| B2. 一律放数据目录下的 `run/` | 简单，统一。要处理掉电后残留的文件（同样靠进程号判断） |

### C. 默认端口，以及同一主机多位主人怎么不撞

| 方案 | 后果 |
| --- | --- |
| C1. 一个固定的默认端口，被占就报错 | 最简单。多人共用的主机上第二个人一启动就失败，要手工改端口。不可接受 |
| C2. 每次启动都用系统分配的空闲端口（监听端口 0），写进运行时文件，命令行从文件读 | 永不冲突。但**每次重启网址都变**：浏览器书签失效；网页的源（含端口）变了，浏览器里存的登录 Cookie、本地存储全部作废，等于每次更新都要重新登录；组网地址上的成员也找不到它 |
| C3. 按 uid 派生：端口 = 基数 + (uid mod N) | 确定、可预测、多数情况下不撞（Linux 普通用户的 uid 从 1000 连续分配，macOS 从 501，Windows 用 SID 末段的 RID，从 1001 起）。但仍可能和别的程序撞，也可能两个 uid 同余 |
| **C4. C3 作为首选端口 + 被占时顺序找空闲 + 选定后记住**：首次启动时按 C3 算出首选端口，被占就往后找一个空闲的；选定的端口写进数据目录的配置，以后一直用它；每次启动把实际监听的端口写进运行时文件，命令行一律从运行时文件读，不猜 | 网址稳定（书签、Cookie 不失效）；多人主机上基本不需要人管；真撞了（比如别的程序后来占了它）时，启动换一个空闲端口、写进运行时文件，并在 `daisy status`、日志里明确说“端口变了，原因是什么、怎么固定回去”。主人也可以显式指定端口（`daisy start --port` 或设置项），指定的端口被占就报错，不悄悄换 |

### D. 基数选在哪里

端口段要避开：各系统的临时端口范围（Linux 默认 32768–60999；Windows、macOS 49152–65535）；常见开发工具的端口（3000、5173、8000、8080、8787 等）。IANA 登记表里 10000–32767 之间最大的一段未分配端口是 **29170–29998**（2026-11-16 查 IANA 的服务名与端口号登记表）。

| 方案 | 后果 |
| --- | --- |
| **D1. 本机面 = 29200 + (uid mod 390)，即 29200–29589；对外面 = 29600 + (uid mod 390)，即 29600–29989** | 整段都在 IANA 未分配区，低于所有系统的临时端口范围；本机面和对外面成对、好记（对外面 = 本机面 + 400）。例：Linux uid 1000 → 本机 29420、对外 29820；macOS uid 501 → 29311、29711 |
| D2. 一个好记的单一端口（比如 4747），多人时 +1 往后找 | 单人电脑上最好记，但多人主机上就退化成“谁先启动谁拿走”，端口随启动顺序变 |

已知会撞的情况：Windows 上 Hyper-V、WSL、Docker 会随机保留一些端口段（`netsh int ipv4 show excludedportrange protocol=tcp` 可见），可能落在任何位置。C4 的“被占就找空闲并记住”覆盖这种情况。

## 推荐

1. **数据目录：A1**。
   - Linux：`$XDG_DATA_HOME/daisy`，默认 `~/.local/share/daisy`
   - macOS：`~/Library/Application Support/Daisy`
   - Windows：`%LOCALAPPDATA%\Daisy`
   - 可以用环境变量 `DAISY_HOME` 或 `daisy start --data-dir` 整体改到别处（测试、同一账户跑多个 Daisy 时用）。目录名来自 P0-06 的名字常量。
   - 目录内的布局（建议）：`daisy.sqlite`（及 WAL 文件）、`keys/`（身份私钥、TLS 密钥、ACME 账户、`master.key`，ADR-099）、`config.json`（含记住的端口）、`backups/`（ADR-104）、`attachments/`、`logs/`、`versions/`（自管更新时，ADR-104）、`run/`（无 `$XDG_RUNTIME_DIR` 时）。目录 0700、文件 0600；Windows 按 ADR-099 的 ACL 做法。
2. **运行时文件：B1**。文件名 `daisy.json`（0600），内容：进程号、版本、本机面网址、对外面网址（如开启）、启动时间、数据目录。命令行先读它，再对本机面发一个带本机凭据的健康检查确认是这个 Daisy；文件不在或进程已死，就说“Daisy 没在运行”，并提示 `daisy start`。
3. **端口：C4 + D1**。首选端口按 uid 派生，被占顺序找空闲，选定后记住；主人显式指定的端口不悄悄换；端口变化写进 `daisy status` 和日志。
4. **同一数据目录只允许一个 Daisy**：启动时拿一把排他锁（数据目录里的锁文件，进程退出自动释放）；拿不到就报“这个数据目录已有 Daisy 在运行（进程号 …）”。这取代现有 `leadership.ts` 的租约交接（ADR-104 说明更新时怎么交接）。
5. 旧的 `.data`、`~/.local/share/agent-harbor` 不读、不迁（旧版已停用，没有迁移包袱）。

## 对工作包的影响

- **P0-06**：名字常量里加数据目录名（`daisy` / `Daisy`）、环境变量前缀 `DAISY_`、运行时文件名。
- **P1-03**：端口规则按本记录；本机凭据文件放在 `keys/` 下。
- **P1-04**：数据库文件名 `daisy.sqlite`，位置按本记录。
- **P1-07**：命令行从运行时文件找 Daisy，不猜端口；`daisy status` 打印数据目录、两个面的网址、端口来源（派生 / 记住的 / 指定的 / 临时换的）。
- **P1-09**：systemd 用户单元里不写端口和数据目录（用默认规则），也不写 `HOST`。
- **P1-12**：加一条测试：同一主机两个系统账户各起一个 Daisy，端口不同、互不干扰；端口被占时换端口并记录。
- **P5-04、P5-05**：macOS、Windows 的路径和 RID 取法；Windows 的保留端口段。

## 待维护者决定的问题（已答复：按推荐，A1、C4 + D1）

1. **数据目录按各系统惯例放（A1），还是三个系统统一一个点目录（A2）？** 推荐 A1。A2 文档更好写，但不合 macOS、Windows 的习惯。
2. **端口规则：同意“按 uid 派生首选端口、被占就找空闲、选定后记住”（C4）吗？基数用 29200（本机面）和 29600（对外面）可以吗？** 推荐同意。如果你更想要一个好记的固定数字，可以换基数，规则不变。
3. **目录名就叫 `daisy` / `Daisy` 吗？** 和 `~/.daisy` 不冲突；其他叫 Daisy 的程序如果也用同样的惯例路径会撞，目前没查到这样的程序（未穷尽）。若想更保险可以用 `daisy-agent`，代价是和命令名不一致。
