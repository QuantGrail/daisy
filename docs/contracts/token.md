# 令牌契约

版本：0.1　状态：草稿，待维护者评审
修订：0.1（2026-11-16）初稿。0.1.1（2026-11-17，阶段 2 关口，维护者的决定）4.2 第 3 步与第 5 节：外部签发方签给主人的令牌有效期上限 24 小时（`exp - iat`），没有 `iat` 拒绝。 0.1.3（2026-11-17，P4-12）第 7 节加实现说明（`me`、移除联系人、重置、吊销的范围），不改格式和规则。0.1.4（2026-11-17，阶段 4 关口，维护者的决定：身份编号统一用 base32）第 2 节 `kid`、4.1 第 3 步：自签发令牌的 `kid` 只能是 base32 身份编号（52 个字符，identity-card.md 第 3 节），base64url 指纹写的 `kid` 一律拒绝；此前实现两种都收（ADR-120 第 7 节第 3 条、审查 L-5）。0.1.2（2026-11-17，P4-04，P4-01 审查的两条）4.1 第 5 步：`client_id` 为 `a2a` 的令牌 `aud` 只能正好是被访问的这个 Daisy（不接受列了别人的数组）；加第 6a 步：联系人签的令牌只能用一次（`jti` 记到 `exp` + 时钟误差）。
共用范围：这一份是几家共用的契约之一。Daisy、外部的任务与聊天系统、以插件接入的组织内部集成的签发方都照它签发和验证。人评审通过之前不算定稿。

依据：设计要求（令牌用 OAuth2 的签名令牌格式；AI 令牌有效期不超过 1 小时；令牌写明签发方、主人、实际操作的 AI 和发给哪个 Daisy）、细分权限、维护者的决定（独立模式下别人的 Daisy 用公钥互认，配了外部签发方时凭它签的令牌互认）、P2-01、P2-02；`docs/research/auth-mcp-a2a.md`。
密码学部分依 ADR-099（提议中）：签名用 Ed25519，令牌用 JWS/JWT（`alg` 为 `EdDSA`），实现用 Node 内置的 `node:crypto`，不引第三方 JOSE 库。ADR-099 定稿前，本文这部分随它改。

## 1. 用什么格式

令牌是 **JWT 访问令牌**，照 RFC 9068（OAuth 2.0 的 JWT 访问令牌格式），用 JWS 紧凑序列化（`头.载荷.签名`，三段 base64url）。代理身份照 RFC 8693 的 `act` 声明。

选它的理由：它就是“OAuth2 的签名令牌格式”的标准写法（标准优先）；外部签发方（比如一个组织自己的登录服务）多半本来就签这种令牌；MCP 授权规范也按 OAuth 2.1 的 Bearer 令牌走，不用两套。

## 2. 头

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| `typ` | `at+jwt` | RFC 9068 要求。验证方只接受 `at+jwt` 或 `application/at+jwt`，以免把别处的身份令牌当访问令牌用 |
| `alg` | 自签发：`EdDSA`。外部签发：`EdDSA`、`ES256`、`RS256` 之一 | 永远拒绝 `none` 和对称算法（`HS*`）。算法按白名单匹配，不信令牌自己说的 |
| `kid` | 签名公钥的编号 | 自签发时就是签发方的身份编号（base32 小写、52 个字符，见 identity-card.md 第 3 节；不是 `iss` 里那段 base64url 指纹）；外部签发时是签发方 JWKS 里那把钥匙的 `kid` |

## 3. 载荷

| 声明 | 必填 | 含义 | 自签发时怎么填 |
| --- | --- | --- | --- |
| `iss` | 是 | 签发方 | `urn:ietf:params:oauth:jwk-thumbprint:sha-256:<指纹>`（RFC 9278；指纹是签名公钥的 RFC 7638 JWK 指纹，base64url）。外部签发方填它自己的签发方标识（一个 https 地址） |
| `sub` | 是 | 主体：这张令牌代表的**人** | 自己的令牌填自己的 `iss`（一个 Daisy 只有一位主人，钥匙就代表他）。替联系人签的 `daisy token` 填那位联系人的 URN |
| `aud` | 是 | 发给谁：只有这一方能接受 | 被访问那一方的标识。对一个 Daisy 就是它的 URN（同 `iss` 的写法）；可以是数组 |
| `exp` | 是 | 过期时间（秒） | 见第 5 节 |
| `iat` | 是 | 签发时间（秒） | |
| `nbf` | 否 | 生效时间 | 一般不填 |
| `jti` | 是 | 令牌编号，随机 128 位，base64url | 用于吊销和审计 |
| `client_id` | 是 | 经哪个通道、哪个客户端拿到的 | 自签发时取下面“通道”表的值；外部签发方填它自己的客户端编号 |
| `scope` | 是 | 允许哪类操作，空格分隔 | 见 scopes.md |
| `act` | 否 | 实际在操作的 AI（RFC 8693） | `{"sub": "<AI 编号>", "name": "<显示名>"}`。有 `act` 的令牌一律按“AI 代主体操作”对待 |
| `name` | 否 | 主体的显示名（OIDC 标准声明） | 只用于显示，不参与任何判断 |

`act.sub` 是签发方范围内唯一的不透明字符串。Daisy 签发时写 `agent:<agentId>`，`agentId` 是会话编号或常驻 agent 的配置编号。别的签发方可以用自己的写法，验证方不解析它。

**通道（`client_id` 的取值，自签发时）**

| 值 | 是谁 | 对应细分权限里的身份 |
| --- | --- | --- |
| `web` | 本地网页 | 主人本人 |
| `device:<设备编号>` | 配对过的设备（P5-03 实现为带设备标记的不透明会话串，通道 `device`，ADR-142） | 主人本人 |
| `cli` | 命令行 | 命令行（可能是主人，也可能是主人的 AI，按后者对待） |
| `ai:<会话编号>` | AI 的工作凭据，带 `act` | AI 工作凭据 |
| `a2a` | 一个 Daisy 调用另一个 Daisy 时临时签的访问令牌，带 `act` | 来访者 |
| `token:<jti>` | `daisy token` 给第三方 A2A 客户端签的 | 来访者 |

本机的四种凭据（命令行凭据文件、网页会话、配对设备凭据、AI 工作凭据）在实现上可以不是 JWT，比如一段只有主人可读的随机串。**但它们验证之后必须得到和上表一样的“认证结果”**：主体、代理（有没有 `act`）、通道、scope。跨出一台机器的令牌（第 4.1、4.2、6、7 节）必须是本文的 JWT。

## 4. 两种情况各怎么验证

两种签发方可以同时存在（维护者的决定：配置外部签发方后，原来互认的联系人照样认得）。验证方按 `iss` 分流：等于配置的外部签发方 → 4.2；是自己或通讯录里某位联系人的 URN → 4.1；都不是 → 拒绝（401）。

### 4.1 自签发（独立模式）

1. 拆开三段。`typ` 是 `at+jwt`，`alg` 是 `EdDSA`，否则拒绝。
2. 按 `iss` 找公钥：自己的，或通讯录里的联系人。找不到就拒绝。被移除的联系人立即找不到（P4-01：移除后对方立即不被认得）。
3. `kid` 必须等于这把公钥算出来的身份编号（base32 小写，原样比较）。同一把钥匙的 base64url 指纹写在 `kid` 里也拒绝（维护者的决定：身份编号只有一种写法）。
4. 用这把公钥验签名（`node:crypto` 的 `crypto.verify(null, 数据, 公钥, 签名)`）。
5. `aud` 里必须有自己的 URN。不是发给自己的令牌一律拒绝，也不转发（MCP 规范“禁止令牌透传”同理）。跨 Daisy 访问令牌（`client_id` 为 `a2a`）的 `aud` 必须正好是自己的 URN 一个值（P4-04）。
6. `exp` 晚于现在，`iat` 不晚于现在，各允许 60 秒时钟误差；`exp - iat` 不超过这个通道的上限（第 5 节）。
6a. 联系人签的令牌只能用一次：`jti` 按联系人记下，保留到 `exp` + 时钟误差，同一个再来就拒绝（P4-04；“每次请求现签一张”，第 5 节）。
7. 通道是 `token:<jti>` 的，查本机的签发记录，已吊销或查不到就拒绝。
8. 得到认证结果：
   - `iss` 是自己、`sub` 是自己、没有 `act`：按 `client_id` 是主人本人或命令行。
   - `iss` 是自己、有 `act`：AI 工作凭据。还要核对这一轮仍在进行，结束了就拒绝。
   - `iss` 是自己、`sub` 是某位联系人（`daisy token` 签的）：来访者，身份是那位联系人。
   - `iss` 是联系人：来访者，身份是这位联系人，实际操作的 AI 是 `act.sub`。
9. 来访者只能走 A2A 入口，不论令牌里写了什么 scope。

### 4.2 外部签发

配置（属于“放别人进来”，要 PIN）：

| 配置项 | 说明 |
| --- | --- |
| 签发方标识 | 必须与令牌的 `iss` 完全相等 |
| 元数据地址 | RFC 8414 的 `/.well-known/oauth-authorization-server`，或 OpenID Connect Discovery。从里面取 `jwks_uri` 和令牌端点 |
| 主人的主体 | 哪个 `sub` 是这个 Daisy 的主人。只有它得到主人身份 |
| 本方标识 | 这个 Daisy 在签发方那里的受众标识，验证 `aud` 用。默认是这个 Daisy 的 URN |

验证：

1. `typ`、`alg` 同 4.1（外部签发多允许 `ES256`、`RS256`）。
2. 按 `kid` 在缓存的 JWKS 里找公钥。找不到时重新取一次 JWKS（每分钟最多一次），还找不到就拒绝。
3. 验签名、`iss`、`aud`、`exp`、`iat`，同 4.1。**`sub` 是主人的令牌（不论有没有 `act`）有效期上限 24 小时**（维护者的决定，阶段 2 关口）：`exp - iat` 超过 24 小时就拒绝（正好 24 小时可以，多 1 秒就不行；这是令牌自己两个声明之差，不加时钟误差）；没有 `iat` 的令牌一律拒绝（`iat` 本来就是必有的声明，所以缺 `iat` 的主人令牌不会被当作“寿命未知、放行”）。别人的令牌（来访者）不受这一条限制。数值见 limits.md 第 5 节（`TOKEN_LIMITS.externalOwnerMaxS`）。
4. **离线验证**：JWKS 缓存在本地，有效期按响应的缓存头，没有就 1 小时。签发方暂时连不上时继续用缓存的公钥（本机优先），并在 `daisy status` 里提示。
5. 得到认证结果：
   - `sub` 是主人、没有 `act`：主人本人。不需要配对。
   - `sub` 是主人、有 `act`：AI 代主人操作，权限按 AI 工作凭据。
   - `sub` 不是主人：来访者，身份是这个 `sub`，只能走 A2A 入口。
6. 签名不对、过期、`aud` 不对：401。

### 4.3 拒绝时回什么

| 情况 | HTTP | `WWW-Authenticate` |
| --- | --- | --- |
| 没带令牌、令牌坏了、签名不对、过期、不是发给我的、签发方不认得 | 401 | `Bearer error="invalid_token"`，不说是哪一条不对 |
| 令牌有效但 scope 不够 | 403 | `Bearer error="insufficient_scope", scope="<需要的 scope>"` |
| 令牌有效、scope 够，但这个身份不能用这个入口（比如来访者访问本机接口） | 403 | 同上一行，scope 写需要的那个 |

错误信息里不出现令牌本身。A2A 入口上的写法见 a2a-usage.md 第 9 节。

## 5. 有效期

具体数值集中在 limits.md，这里只列规则。

| 令牌 | 默认 | 上限 | 说明 |
| --- | --- | --- | --- |
| 跨 Daisy 的访问令牌（`a2a`） | 5 分钟 | 5 分钟 | 每次请求现签一张。阻塞等待的请求只在到达时验一次，连接扣着不受过期影响 |
| AI 工作凭据（`ai:`） | 到这一轮结束 | 1 小时 | 一轮结束立即作废；一轮超过 1 小时由 Daisy 换新的交给 MCP |
| 替 AI 代领的令牌（第 6 节） | 1 小时 | 1 小时 | 到期前重新领 |
| `daisy token`（`token:`） | 7 天 | 90 天 | 可以单独吊销 |
| 外部签发方签给主人的令牌（`sub` 是主人） | 由签发方定 | 24 小时 | `exp - iat` 超过就拒绝，没有 `iat` 也拒绝；存着用于令牌交换的主人令牌同样 |
| 外部签发方签给别人的令牌（来访者） | 由签发方定 | — | 只验 `exp`（本机接口一律拒绝，阶段 4 的 A2A 入口才用） |

## 6. 替 AI 代领令牌（P2-02）

AI 有时要拿令牌去访问别的系统（比如一个组织内部系统的接口）。Daisy 替它领，交给 harness 里需要它的 MCP。

**要求**：令牌上写明主人（`sub`）和实际操作的 AI（`act.sub`）；scope 不超过主人能有的；有效期不超过 1 小时。

**独立模式**：Daisy 自己签。`iss`、`sub` 是自己，`act` 是这个 AI，`aud` 是要访问的那一方，`client_id` 是 `ai:<会话编号>`。

**外部模式**：照 RFC 8693 令牌交换，向外部签发方的令牌端点请求：

| 参数 | 值 |
| --- | --- |
| `grant_type` | `urn:ietf:params:oauth:grant-type:token-exchange` |
| `subject_token` | 代表主人的令牌（配置外部签发方时，主人登录一次留下的，存在只有主人可读的文件里） |
| `subject_token_type` | `urn:ietf:params:oauth:token-type:access_token` |
| `actor_token` | Daisy 自签的一张短令牌，`sub` 是 `agent:<agentId>`，说明是哪个 AI |
| `actor_token_type` | `urn:ietf:params:oauth:token-type:jwt` |
| `scope` | 要的 scope，必须是主人有的子集 |
| `resource` 或 `audience` | 要访问的那一方 |

Daisy 向令牌端点证明自己时用 `private_key_jwt`（RFC 7523，用身份密钥签）。

**领回来之后 Daisy 自己再验一遍**：`sub` 是主人；`act.sub` 是这个 AI；`scope` 不超出请求的；`exp - iat` 不超过 3600。任何一条不满足就不交给 AI，记一条审计，并告诉 AI 拿不到令牌。

**对外部签发方的要求**（写给接入的签发方）：签 RFC 9068 格式的 JWT；公开 JWKS；支持 RFC 8693 令牌交换并在结果里写 `act`；给 AI 的令牌有效期不超过 1 小时。

## 7. 第三方 A2A 客户端：`daisy token`

不是我们写的 A2A 客户端没有我们的签名逻辑。给它一张现成的令牌，按标准 Bearer 方式带上，agent 名片上声明的认证方式就是标准的。

```
daisy token issue --for <联系人|me> [--ttl 7d] [--note "给 CI 用"]
daisy token list
daisy token revoke <jti>
```

- 属于“放别人进来”：要 `daisy:grant` 和 PIN。
- 签出的令牌：`iss` 是自己；`sub` 是那位联系人（`--for me` 时是自己）；`aud` 是自己；`scope` 只有 `daisy:invoke`；`client_id` 是 `token:<jti>`；没有 `act`。
- 拿着它的人以那位联系人的身份调用，仍要过调用授权（粒度是每个 agent × 每个人；单向、不传递、只含调用、可撤销）。`--for me` 签出的令牌也只能走 A2A 入口，**不给主人身份**，不能访问本机接口。
- 签发记录（jti、给谁、备注、到期时间，不存令牌本身）存在本机，`list` 列出，`revoke` 立即作废。
- 命令只打印一次令牌，并提示：谁拿到它谁就能以这个身份调用，像密码一样保管。
- 实现（P4-12，ADR-132）：`--for me` 的持有者在调用授权里是一个单独的人（“我自己”，不是联系人），照常要开放范围和批准；联系人被移除时他名下的令牌一并作废；重置 PIN 时全部作废；吊销只拒绝之后的请求，已经开始的任务不受影响。

## 8. 安全说明

- 签名私钥存数据目录里只有主人可读的文件（依 ADR-099，提议中）。AI 以主人的系统账户运行，**读得到这把私钥**，所以理论上可以自己签令牌冒充主人去调用联系人的 agent。这是已知限制（AI 以主人的系统账户运行，主人能读的它都能读）的延伸：给 AI 收窄的 scope 在本机上只是约定。PIN 保护的那一类不受影响，因为签令牌不需要 PIN，但“放别人进来”的接口另外要 PIN。
- 令牌只放 `Authorization: Bearer` 请求头，不放进 URL（MCP 授权规范的 MUST）。
- 日志里只记 `jti` 和 `client_id`，不记令牌。
- 自签发只用 `EdDSA`。RFC 9068 要求合规的一方“支持 RS256”；Daisy 作为验证方支持它（外部签发），作为签发方不用它。这是一处有意的偏离。
