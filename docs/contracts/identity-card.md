# 身份名片契约

版本：0.1　状态：草稿，待维护者评审
修订：0.1（2026-11-16）初稿。 0.1.3（2026-11-18，P5-02，ADR-144）第 3 节：中转子域名是身份编号的前 32 个字符（原来写“52 个字符的身份编号可以直接当子域名”，与 ADR-100 和中转协议不一致）；第 1 节 `addrs` 的 `relay` 地址由中转给出，停用中转后导出的名片里不再有它。 0.1.1（2026-11-17，ADR-128）第 6 节补独立 A2A MCP 的存放和导入（没有 PIN，用确认）；名片的生成和验证代码在 `packages/a2a-client`，Daisy 和 MCP 共用。0.1.2（2026-11-17，阶段 4 关口，维护者的决定）第 6 节：导出名片、列出、查看联系人和只看一张名片在网页等主人入口不要 PIN，本机命令行要（仍要 `daisy:grant`）；第 3 节：令牌头的 `kid` 只认 base32 身份编号，base64url 指纹写的 `kid` 拒绝。

依据：设计要求（身份名片和 agent 名片是两种名片；独立模式下公钥互认；私人 agent 也要有身份）、P4-01、P4-09。密码学部分依 ADR-099（提议中）：Ed25519 签名，身份编号是公钥的 SHA-256 指纹，私钥存数据目录里只有主人可读的文件。

身份名片和 agent 名片是两样东西。本文只管身份名片：一个 Daisy 一张，互认时交换。agent 名片是 A2A 的 Agent Card，见 a2a-usage.md。

## 1. 字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `v` | 是 | 名片格式的主版本，现在是 `1` |
| `id` | 是 | 身份编号（第 3 节） |
| `key` | 是 | 公钥，JWK：`{"kty":"OKP","crv":"Ed25519","x":"<32 字节公钥的 base64url>"}` |
| `name` | 是 | 主人的显示名，1–64 字。只用于显示 |
| `addrs` | 是，可以为空数组 | 可以连到这个 Daisy 的地址，见下 |
| `iat` | 是 | 生成时间（秒） |
| `note` | 否 | 一句备注，≤200 字，比如“公司那台服务器” |

`addrs` 每一项：

| 字段 | 说明 |
| --- | --- |
| `kind` | `direct`（直连，比如组网地址）或 `relay`（中转给的固定地址：`https://<身份编号前 32 个字符>.<中转域名>[:端口]`；选了中转时导出的名片自动带上，停用后不再带，P5-02） |
| `url` | 这个 Daisy 对外面的根地址，`https://…`（直连在组网内也可以是 `http://`）。agent 名片在它下面，见 a2a-usage.md 第 2 节 |

不装 Daisy、只装独立 A2A MCP 的私人 agent 也有一张身份名片，`addrs` 为空：别人认得它，但没有地址可以调用它。

## 2. 可复制的文本格式

名片导出成一段文本，可以贴进聊天、邮件，或存成文件（扩展名 `.daisycard`，内容相同）：

```
Daisy 身份名片
名字：张三
编号：k7m2 q6xd 4tfa 5wze 3npl 6hcv 2ryb 5sgu 7jke 4mqa 7dxt 3wnf 6pzq
地址：https://zhangsan.relay.example.org
daisy-card:1:eyJhbGciOiJFZERTQSIsInR5cCI6ImRhaXN5LWNhcmQrand0In0.eyJ2IjoxLCJpZCI6…
```

- 给人看的几行用导出时的显示语言写（P6-23b，ADR-159）：上面是中文的样子，英文是 `Daisy identity card` / `Name:` / `Number:` / `Address:` / `Note:`。标签来自语言包（`a2a.card.label.*`；读时认的写法是 `a2a.card.read.*`，包括繁体的 `編號`、`名稱`、`備註`）。**导入时认所有语言的标签**，所以一种语言写的名片在任何语言的 Daisy 和 daisy-mcp 里都按同样的规则核对。
- **只有最后一行是给机器读的**：前缀 `daisy-card:1:`，后面是一个 JWS 紧凑序列化（`头.载荷.签名`）。前面几行是给人看的，导入时程序按载荷重新算一遍；人看的行和载荷对不上就拒绝导入，并说明哪一行对不上。
- 前缀里的 `1` 是格式主版本，与载荷的 `v` 相同。遇到不认识的主版本，拒绝导入并提示“这张名片需要更新版本的 Daisy”。
- JWS 头：`{"alg":"EdDSA","typ":"daisy-card+jwt"}`。载荷是第 1 节的字段。签名用这张名片自己的私钥（自签）。
- 次版本的新增字段只往载荷里加，旧版本读到不认识的字段忽略。
- 整行一般在 600 字符以内，换行或空格被聊天软件插入时，导入前先去掉空白。

## 3. 身份编号和指纹算法

1. 取公钥的 JWK，只留 `crv`、`kty`、`x` 三个成员，按 RFC 7638 规定的写法（成员按字典序、无空白）排成 JSON：
   `{"crv":"Ed25519","kty":"OKP","x":"<base64url>"}`
2. 对它的 UTF-8 字节算 SHA-256，得到 32 字节（这就是 RFC 7638 的 JWK 指纹）。
3. **身份编号** = 这 32 字节的 base32 编码（RFC 4648 字母表），**小写、不带填充**，共 52 个字符。

为什么用 base32 而不用 base64url：

- 中转按子域名把连接递给对应的 Daisy。子域名只能是小写字母、数字和连字符，最长 63 个字符。中转子域名是身份编号的**前 32 个字符**（指纹的前 160 位，ADR-100 推荐 3、`packages/relay/PROTOCOL.md` 第 2 节），所以手里有名片的人能自己算出对方的中转地址；base64url 有大写和下划线，不行。
- 不分大小写，念给对方听、手抄时不容易错；没有 `-`、`_` 这种在不同字体里难分辨的符号。

同一个指纹还有两种写法，都可以从身份编号直接换算出来：

| 用在哪里 | 写法 |
| --- | --- |
| 名片、界面、命令行、日志 | 身份编号（base32 小写，52 字符） |
| 中转子域名 | 身份编号的前 32 个字符（`<前 32 个字符>.<中转域名>`） |
| 令牌的 `iss`、`sub`、`aud`，事件的 `source` | `urn:ietf:params:oauth:jwk-thumbprint:sha-256:<同样 32 字节的 base64url>`（RFC 9278 规定用 base64url） |
| 令牌头的 `kid` | 身份编号（只认这一种写法：base64url 指纹写在 `kid` 里拒绝；维护者的决定：身份编号统一用 base32） |

**给人看时**：每 4 个字符一组，用空格隔开（上面的示例）。当面或电话核对时，至少核对前 16 个字符（80 位）；界面默认显示全部。

## 4. 导入时怎么验证

1. 去掉空白，取 `daisy-card:` 开头的那一行；版本号认得。
2. 解出 JWS 头和载荷。`alg` 是 `EdDSA`，`typ` 是 `daisy-card+jwt`。
3. 用载荷里的 `key` 验签名。
4. 按第 3 节重新算身份编号，必须等于载荷的 `id`。
5. 人看的几行（如果有）与载荷一致。
6. `id` 等于自己的：拒绝（不能加自己）。`id` 已在通讯录里：作为“更新”处理，显示新旧差异（名字、地址），主人确认后替换。
7. 把名字和完整的身份编号显示给主人，提示“请和对方核对编号”，主人输入 PIN 后才加入通讯录（设计要求：添加名片要 PIN）。可以同时勾选“加进白名单”，之后对方第一次调用不弹卡片（维护者的决定）。

**名片本身只证明“这段内容是这把钥匙的主人发的”，不证明“这把钥匙是张三的”。** 后者靠主人和对方在别的渠道核对编号。这一点要写进界面上的提示。

## 5. 换钥匙、换地址

- **换地址**（换了中转、组网地址变了）：重新导出名片发给对方，对方导入时走第 4 节第 6 步的“更新”。钥匙不变，身份编号不变，已有授权都在。
- **换钥匙**：这一版不支持。换钥匙等于换了一个人：身份编号变了，对方要重新加名片，授权要重新给。重置 PIN 不换钥匙（重置 PIN 吊销的是对外授权、联系人和设备，不是自己的身份）。以后如果要支持，用旧钥匙签一张“换钥声明”，在次版本加。

## 6. 存放

- 私钥：数据目录里只有主人可读的文件（依 ADR-099，提议中）。首次启动生成。
- 通讯录：数据库里，存每张名片的完整 JWS、身份编号、加入时间、是否在白名单。
- 导出名片、列出、查看联系人和只看一张名片是谁的（不写入）：网页、配对设备、外部签发方给主人的令牌不需要 PIN（名片是公开的）；本机命令行要 PIN（维护者的决定：命令行凭据可能是主人的 AI）。导入、移除、加入或移出白名单在哪儿都要 PIN。和整组一样要 `daisy:grant`：AI 的工作凭据和来访者读不到。
- **独立的 A2A MCP**（P4-09，ADR-128）：私钥、通讯录放在它自己的目录（`--home`、`DAISY_MCP_HOME` 或系统的配置目录，不是 Daisy 的数据目录），目录 0700、文件 0600；通讯录只存每张名片的 JWS，每次读出都按第 4 节重新验证。它没有 PIN：导入、移除要主人在命令行确认（`--yes` 或终端里输入），可以带 `--expect-id` 核对编号；第 4 节第 1–6 步与 Daisy 用同一份代码（`packages/a2a-client/src/card.ts`）。它的名片 `addrs` 为空。
