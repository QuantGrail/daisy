# 工作区并行与只读分析

使用说明（新建会话时怎么选、各系统上的差异）见用户指南 [harness 支持范围](guide/zh-CN/harnesses.md) 的“工作目录的四种方式”。这里补充设计上的边界。

## 四种方式

| 方式 | 取值 | 文件来源 | 并行方式 |
| --- | --- | --- | --- |
| 共享编辑 | `shared`（默认） | 所选目录的当前文件 | 会话可同时运行；避免同时修改同一文件 |
| 只读分析 | `read-only` | 所选目录的当前文件 | 可与编辑会话并行，读到的内容可能随文件变化 |
| 独立开发 | `isolated` | 独立的 Git worktree 和分支 | 各自修改，由你整合 |
| 版本审查 | `snapshot` | 固定在一个提交上的只读 Git worktree | 不受原目录之后的编辑影响 |

## 不做什么

Daisy 不按会话、目录或文件串行化 AI 的工作，也不自动合并冲突。共享目录里，Codex、Claude Code 等工具自己的编辑检查照常起作用，但它们不等于跨进程的防覆盖保证。需要各改各的，用独立开发；同一个共享目录里协作，要事先分工。每个会话内各轮的先后顺序照旧保证。

后台任务和 harness 自己的定时器照常运行，不会因为别的会话用同一个目录而被暂停。独立的任务应使用各自的输出目录。

## 独立开发与版本审查

两者都调用原生的 `git worktree add`，从已提交的 HEAD 开始，不复制原目录里未提交的修改（原目录有未提交改动时，独立开发拒绝创建，请先整理提交）。新建的 worktree 放在仓库 Git 目录下的 `daisy-worktrees/<会话号>`，分支是 `daisy/<会话号>`；改名前建的（`harbor-worktrees/`、`harbor/<会话号>`）照旧找得到、照旧使用。每个会话复用自己的 worktree，Daisy 不自动更新、提交、合并或删除它。分支和元数据由 Git 自己管理，Git 拒绝操作时直接报告错误。

## 强制只读

只读分析用 Bubblewrap 强制执行：源文件和其他路径只读，只有当前 harness 必需的状态目录和私有临时目录可写；源目录和可写的状态目录不得重叠。它需要 Linux、可用的 `/usr/bin/bwrap`，以及你在这台机器上已有的 harness 登录状态。能力缺失或隔离失败时报错，不降级成可写会话。只读不提供文件快照，需要稳定的版本时选版本审查。文件系统只读不收回已经允许的网络访问。

在 macOS、Windows 上，Daisy 自己没有强制只读；各家 harness 的“问”能做到多强，见用户指南里的系统差异表。
